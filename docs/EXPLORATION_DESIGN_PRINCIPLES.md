# 镜像岛探索设计原则

## 定位与状态

本文保存镜像岛长期可复用的探索设计语言，目标是在种田、生活和小镇循环中增加冒险感，而不是复制大型开放世界的内容体量。

本文是未来生活世界探索候选的评审依据，不自动授权任何功能实施。当前 P1 只批准小镇共建簿与地表采矿进入既定规划；其他探索、谜题或新状态必须先形成独立范围并获得批准后才能进入代码。

参考成熟冒险游戏时只吸收抽象设计方法，不复制其品牌、地图、角色、文本、谜题答案、音乐、UI、图标或素材。

## 核心体验循环

每个探索内容都应尽量形成完整的五步体验：

1. **看见异常**：玩家通过构图、地标、声音、光线、NPC 行为或环境变化察觉“这里值得留意”。
2. **获得线索**：环境、时间、NPC 对话或已有生活规则提供足以推理的信息，不依赖外部攻略。
3. **主动尝试**：玩家使用移动、观察、现有工具或已经掌握的世界规则完成尝试。
4. **得到明确反馈**：画面、声音和文字共同说明操作是否有效，避免无提示的像素级试错。
5. **留下有意义的结果**：奖励改变后续选择、路线、知识或世界表现，而不是只弹出一次数值。

若候选内容无法说明上述五步，应先收缩或重做设计，不以增加提示箭头、任务面板或通用框架掩盖体验缺口。

## 设计原则

### 1. 手工微发现优先

- 优先在固定地图中制作少量、可记住的秘密，不建设无界程序生成或批量模板谜题。
- 一个发现只验证一个主要概念；地点、线索、解法和奖励必须彼此呼应。
- 秘密应当是可选惊喜，不能用模糊线索阻塞基础种田、商店、睡觉或存档恢复。
- 内容密度服从“一张精美地图优先于十张粗糙地图”，不靠收藏清单制造虚假体量。

### 2. 先复用已有动作

- 设计新能力前，先验证移动、观察、NPC 对话、昼夜和已有工具能否完成目标。
- 锄头、水壶、斧头等生产工具可以各自获得少量清晰的环境用途，但同一纵向切片不扩建完整物理、元素反应或通用谜题系统。
- Durable mutation 仍由 `GameSession` 统一处理；Phaser/Vue 只发送命令并渲染 snapshot，不能为了秘密内容直接写存档或复制规则。
- 只有真实内容需要重复使用时才提取窄合同，不因“以后可能有用”提前建设框架。

### 3. 时间是软选择，不是惩罚条

- 利用现有时钟、昼夜和 NPC 日程形成“现在继续探索，还是回家完成生活安排”的自然取舍。
- 黄昏、夜晚或特定日程可以改变线索和环境，但关键条件必须能被观察、获知并再次尝试。
- 不为制造冒险感默认增加体力、饥饿、武器耐久、死亡掉落或强制倒计时。

### 4. 用地标牵引，而非 HUD 牵引

- 优先用远景轮廓、构图留白、光色、环境声、道路朝向和 NPC 只言片语引导注意力。
- 地标应先产生问题，再逐步给出答案；允许玩家暂时看见但无法解释。
- 任务箭头、全知小地图和逐步答案只在可访问性或真实迷路问题得到证据后评审。

### 5. 奖励优先改变世界或选择

- 优先奖励新配方、特殊种子、短路、环境恢复、NPC 新反应或后续可识别的世界变化。
- 纯 Gold、普通材料或单次提示可以作为附属奖励，不能成为所有秘密的唯一结果。
- 永久变化必须有明确 owner、保存边界与恢复行为；纯表现变化不得反向污染 domain state。

### 6. 发现需要仪式感

- 使用原创的声音、粒子、短暂停顿、动画或克制文本共同确认发现。
- 反馈不能只依赖颜色、声音或细小像素中的单一通道，应兼顾弱视、静音和不同缩放比例。
- 仪式感服务于理解和记忆，不用长演出打断日常生活节奏。

### 7. 世界变化重于内容数量

- 完成发现后，玩家再次经过应能看见某种结果或理解变化的原因。
- 优先让既有 Town、Foothills、Lakeshore 和 NPC 产生新的可感知关系，不为了秘密重排已冻结的 Farm v1 或 Town 大构图。
- 新入口和独立区域必须有真实用途；不以空门、空面板或只有一句“以后再来”的占位物假装世界更大。

## 首次验证模板

未来若单独批准第一个探索纵向切片，默认先验证三个可选微发现，而不是建立完整系统：

| 地点 | 主要发现方式 | 推荐结果 |
|---|---|---|
| Town | 观察构图或 NPC 行为 | 配方或人物新反应 |
| Foothills | 使用一种已有工具 | 特殊种子或环境恢复 |
| Lakeshore | 时间条件加 NPC/环境线索 | 可见且可恢复的世界变化 |

三处内容合计目标为约 10～15 分钟；每处只保留一个主要规则，并分别说明地点、线索、动作、成功反馈、奖励、保存需求和失败后的再次尝试方式。模板不授权具体点位、奖励或存档字段。

## 明确不随探索理念自动进入范围

- 战斗、敌人、伤害、攀爬、滑翔、武器耐久、体力或复杂生存状态。
- 程序生成地图、通用物理沙盒、元素反应矩阵、通用任务引擎或通用谜题编辑器。
- 大量收集物、地图清单、重复宝箱、纯数值遗物或用货币填充每个角落。
- 将当前家园猫狗 MVP 扩展成寻宝、农场工作、战斗伙伴或通用动物框架。
- 通过探索内容重新包装用户已经否决的镜门远征、Expedition Cargo、撤离、抓宠、肉鸽或塔防。

## 候选玩法评审清单

任何探索候选进入 PRD 前，必须能简要回答：

- 玩家首先在哪里、通过什么可感知异常注意到它？
- 线索来自环境、NPC、时间还是已有规则，玩家为什么能够推理？
- 玩家使用哪个已有动作；新增命令或状态真的不可避免吗？
- 成功、失败和条件未满足时分别得到什么明确反馈？
- 奖励如何改变选择、路线、知识、人物关系或世界表现？
- 是否需要持久化；若需要，谁拥有 mutation、校验和恢复？
- 是否影响 Farm v1、Town 大构图、当前里程碑或已冻结能力？
- 本次明确不建设哪些相邻系统？
- 可以用哪条 5～15 分钟真人路线验证“观察—推理—尝试—反馈—变化”完整成立？

如果答案主要依赖未来内容、通用框架或大量资产，候选应继续收缩，不进入实施。
