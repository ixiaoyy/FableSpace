# FableSpace 角色故事平台主线

本文档定义 FableSpace 当前 P0 的产品主线和能力边界。产品定位见 [PRODUCT_BRIEF.md](PRODUCT_BRIEF.md)，数据合同见 [WORLD_SCHEMA.md](WORLD_SCHEMA.md)，负面边界见 [WHAT_NOT_TO_BUILD.md](WHAT_NOT_TO_BUILD.md)。

## 主线定位

FableSpace 是一个**角色故事平台**。玩家因为想见一个角色而进入其所属的完整故事世界，通过对话和选择建立关系、经历事件，并在回访时延续已有结果。

角色是公开发现入口，故事世界是角色正史、规则和连续性的边界。一个 Character 可以参与所属 StoryWorld 内一个或多个经过审核、可独立发布且随世界内容版本追踪的 ReviewedStory；平台不要求玩家先浏览世界目录或故事大厅，也不提供全局身份选择。玩家选择角色后，在角色详情选择可进入的已发布故事（只有一个时直接使用），再让所属 StoryWorld 的单一 PlayerRole 自动生效，或在多个系统审核身份中为新 StoryRun 选择一个。

当前只运行由系统策划并经过内容完整性核验的故事内容。一个部署级固定管理员通过内部后台维护当前 StoryWorld；AI 负责在当前内容边界内理解自由输入和演绎角色，不负责创建世界正史、永久结局或未核验的剧情状态。

## P0 玩家闭环

```text
首页直接发现角色
  -> 选择想见的角色
  -> 查看角色当前处境；有多个已发布故事时选择一个
  -> 为新轮次确认该世界允许的 PlayerRole
  -> 登录或确认已有登录会话
  -> 直接进入角色对话
  -> 自由对话 / 人工编写的关键选择
  -> 写回分故事进度与私有记忆，以及长期角色关系
  -> 回访时恢复该故事进度与跨故事关系
```

首页、角色卡、StoryWorld 摘要和 PlayerRole 入场信息允许未登录浏览。开始、恢复、推进或重新开始故事必须具有有效登录会话；未登录点击“进入故事”时先去登录，成功后回到原角色入口。平台不创建匿名进度，也不提供匿名进度绑定、迁移或合并。

## P0 系统故事

当前 P0 公开内容基线只包含两个 StoryWorld 和三个 Character；按目标合同，两个世界现有内容各映射为一个已发布 ReviewedStory：

| StoryWorld / 现有 `story_world_id` | 目标稳定 `story_id` | 类型 / 参与 Character | 系统预设 PlayerRole | 验证目标 |
|---|---|---|---|---|
| 1854 年宽街 / `history_broad_street_water_1854` | `broad_street_water_1854` | `growth` / 安妮（焦点角色） | 汤姆·里德 / 莉齐·贝尔（二选一） | 在不可改写的真实历史时间线内提供原创角色选择和私有后果 |
| 先天二年·虔化门 / `story_palace_snow_edict` | `palace_snow_edict` | `ensemble` / 高力士、太平公主 | 内侍小使 / 宫人（二选一） | 在不可改写的 713 年先天政变结果内验证真人多角色叙事与来源分层 |

`story_id` 是 StoryWorld 内稳定且不可复用的审核内容标识，不从标题、数组顺序、Character 或 `content_version` 推导。当前代码、托管 JSON 与数据库仍使用“一世界一套章节 / 结局”的旧物理结构；上表描述的是后续原子迁移的目标映射，不表示多故事运行时已经上线。

安妮是约十岁的原创角色，不是真实历史人物，也不影射真实未成年人。她以讨水这一具体请求带玩家进入宽街事件；史实通过地点、物件、证词、对话和选择逐步呈现，而不是在入场前作为说明材料倾倒给玩家。

先天二年·虔化门以 713 年七月三日玄宗一方先制入宫、太平公主一方失败及其后公开处置为固定历史骨架。高力士与太平公主分处史书记载的不同位置，不在无同场证据的原创场景直接会面；真人自由回应使用带固定标识的第三人称剧情转述，不生成第一人称原话。玩家可在成年“内侍小使”与“宫人”中选择本轮身份，只能核对门次、抄本、名单与消息来源，不能替真人行动、改变结局或把官修史书指控演成确定的私人内心真相。

青槐驿与临川大学保留为待重新设计的候选内容。在各自系统预设 PlayerRole、角色反应、剧情骨架和连续性完成评审前，不进入 P0 公开发现。

## 核心产品对象

| 对象 | 产品职责 |
|---|---|
| StoryWorld | 承载稳定正史、规则、Character 注册表、系统预设 PlayerRole 和一个或多个 ReviewedStory。 |
| ReviewedStory | StoryWorld 内可审核、可独立发布并随世界 `content_version` 追踪的故事骨架；承载参与角色、类型、章节、选择、确定性角色决策和结局。它是托管内容中的值对象，不是独立数据库实体。 |
| StoryCharacterParticipation | 定义 Character 在一个 ReviewedStory 中的当前处境、开场首句和能否作为入口；同一 Character 在不同故事中可以有不同参与配置。 |
| Character | 保存跨故事稳定的身份、年龄、社会地位、独立欲望、秘密和语言边界，不保存某个故事专属的当前处境或开场首句。 |
| PlayerRole | 定义玩家在一个 StoryWorld 内可被 StoryRun 锁定的称谓、年龄边界、性别、社会地位、背景和入场理由。 |
| PlayerStoryState | 作为玩家与 StoryWorld 的私有状态根，包含按 `story_id` 隔离的故事进度，以及按 Character 延续的长期关系。 |
| StoryRun | 锁定 `story_id`、`content_version` 与 `player_role_id`，保存该轮次可回放的消息、选择、事件和结局。 |
| CharacterRelationship | 保存玩家在一个 StoryWorld 内与一个 Character 的长期关系；跨该世界内的故事和轮次延续，并记录最近变化的来源轮次与事件。 |

`NPC` 只描述 Character 由 AI 演绎的运行方式，不是持久化领域实体名。上述对象的字段、唯一性和存储约束由 [WORLD_SCHEMA.md](WORLD_SCHEMA.md) 定义。

## 系统内容与管理边界

StoryWorld 是系统内容，不是用户创建的店铺、房间或角色卡容器。目标内容流程是：

```text
人工策划并核验 StoryWorld 与 ReviewedStory 合同
  -> 固定管理员进入 StoryWorld
  -> 分别编辑世界设置、背景设定、Character 和 ReviewedStory
  -> 结构校验
  -> 保存为数据库当前内容
  -> 公开 Character 与 StoryRun 只读取已发布 ReviewedStory
```

后台全局导航仍只需要“故事世界”，不建设面向玩家的故事大厅。现有后台使用“世界设置、背景设定、章节管理、角色管理”四个页面，只能维护当前单故事物理结构；多故事管理表面属于后续原子代码任务，不能提前用混合内容树、通用 JSON 编辑器、拖拽搭建或任意样式配置替代审核合同。首页内容配置和独立媒体库继续延期；Character 图片只在角色编辑页上传。

系统内容继续以 `managed_story_worlds` 中每个 StoryWorld 一份 JSON 文档保存；目标文档在世界级正史、规则、PlayerRole 和 Character 注册表之外包含 `stories[]`。ReviewedStory 自带发布状态，因此已发布 StoryWorld 可以同时保存草稿故事，但公开发现、开始、恢复和推进只能读取已发布故事。Python `StoryWorldRegistry` 只作为首次引导来源和结构校验边界；保存时必须把全部当前世界共同校验，拒绝缺失字段、重复 ID、跨世界引用、未发布引用和断裂剧情图。

当前 `managed_story_worlds.payload_json` 仍是世界直接持有 `entry_chapter_id`、`chapters` 和 `endings` 的旧形状。后续迁移必须在一个经批准的版本内显式转换现有托管 JSON，并同步迁移 StoryRun、分故事进度和长期关系；`seed_missing()` 只能补齐缺失的内建世界，不能覆盖管理员内容、猜测默认故事或承担迁移。

StoryRun 在目标合同中同时锁定 `story_id`、`content_version` 与 `player_role_id`。活动轮次不得切换故事或身份；内容变更后如何恢复、封存或重新开始须由明确版本策略处理，不能用兼容解码器、双写或启动时静默修复掩盖旧状态。

普通用户不能创建、编辑或发布 StoryWorld。管理 API 只接受现有可信会话中由 ParallelLines 票据兑换和实时回查确认为 `role=admin` 的账号；该账号进入后自动成为 FableSpace 内容后台管理员，无需维护第二份管理员 ID 配置。未登录或角色不匹配时拒绝访问。当前产品不保留店主、创作者、owner 管理、故事密码、营业状态、内容市场或角色卡导入导出作为隐藏兼容能力。

## 人工剧情骨架与 AI 演绎

每个 ReviewedStory 采用“人工剧情骨架 + AI 角色演绎”的混合推进：

- 系统预先定义参与 Character、章节、节点、关键选择、允许的状态变化、CharacterDecision、关系规则和结局。
- 玩家既可以点击人工编写的选择，也可以自由输入。
- 确定性规则按审核顺序校验剧情动作、前置条件和 CharacterDecision，并决定持久化变化；必须存在明确兜底，不能让 LLM 补决定。
- AI 根据 Character 的身份、年龄、社会地位和语言边界，以及 PlayerRole、当前关系、当前节点、已确认正史和玩家私有连续性生成角色回应。
- 角色节点必须明确区分 Character 对白与系统 / 行动叙述；系统叙述不能冒充 Character 发言，Character 也不能凭空知道未向其公开的消息。
- 只有已定义且校验通过的剧情动作、规则结果或长期关系效果可以推进章节、改变关键标记、改变永久关系或完成结局。

自由输入没有命中剧情动作时仍可形成普通对话和受限的关系反馈，但不能绕过前置条件、创造新正史、跳到未开放节点，或直接决定永久关系、关键标记与结局。任何需要长期保留的状态都必须结构化、可追踪、可回放并可验证。

历史故事的参考内容由玩家主动展开，按当前 StoryRun 阶段从同一审核注册表解锁。页面必须区分“史实 / 剧情设定 / 待核验”并显示既有来源；锁定条目不提前下发，不把说明文案铺满主叙事，也不让 AI 临时补写参考资料。

## 角色关系与连续性

角色关系采用“内部连续好感度 + 故事状态 / 关键标记”的双层模型：

- 自然对话可以依据角色人设和当前语境产生有理由的小幅变化。
- 人工审核的关键选择可以产生较大变化，并打开或关闭分支。
- 重复闲聊不得无成本刷出重大关系阶段或结局。
- 前台不展示好感数值，只展示角色可感知的态度、关系阶段和变化原因。

PlayerStoryState 按玩家与 StoryWorld 隔离，并在该状态根内按 `story_id` 隔离活动轮次、章节、标记、选择、结局摘要和故事私有记忆。一个故事不能读取或改写另一个故事的进度，除非审核内容把某个结果显式提升为世界级长期关系事实。

CharacterRelationship 按玩家、StoryWorld 与 Character 唯一定位，保存在所属世界内，不跨世界传播，也不进入公开资料、排行榜或访客社交。经审核且成功提交的长期关系变化跨 ReviewedStory 和 StoryRun 延续，并记录来源 `story_run_id` 与事件；故事专属标记、选择和结局不得因此泄漏到其他故事。

故事进行中不能撤销关键选择。到达结局后可以明确开始新一轮；新轮次重置该故事的轮次进度与分支标记，但继承已写入的长期 CharacterRelationship。上一轮在玩家私有状态中保留结局摘要和必要回访记录。P0 不提供存档槽、章节回退或同一故事的并行时间线；不同 ReviewedStory 可各自保有一个活动轮次。

跨 Character 访问必须由玩家在当前互动中执行明确动作，并创建可追踪的访问上下文；系统不得因规则结果、角色决定或页面刷新自动把玩家重定向到另一 Character。消息默认只对当前对话 Character 可见，只有审核节点显式列入的 Character 才能获知；系统 / 行动叙述对玩家可见，不等于已对所有 Character 公开。

## 玩家身份边界

每个 P0 StoryWorld 提供一个或多个系统审核 PlayerRole。它属于故事内容，不是账号权限、现实身份、公开资料或可跨世界复用的职业；每个 StoryRun 锁定其中一个，活动轮次中不能更换。

- 进入安妮故事时，从“汤姆·里德”与“莉齐·贝尔”两个原创年轻角色中选择本轮身份；安妮根据锁定身份称玩家为哥哥或姐姐。
- 进入高力士或太平公主时，从成年“内侍小使”与“宫人”中选择本轮身份。
- PlayerRole 的能力必须来自所属世界的时代、制度、背景和入场理由。
- 前台展示简短、可识别的身份名；职责、已知信息和剧情钩子由运行时合同提供。
- 平台不提供全局身份目录、脱离故事的通用性别选择、用户自定义身份 Prompt 或身份等级系统。

## 历史与原创正史边界

所有 StoryWorld 都有已发布正史，但历史题材与原创架空题材的事实约束不同。

### 历史故事

历史故事运行在经过人工核验的真实时间线上：

| 内容层 | 运行规则 |
|---|---|
| 固定史实 | 经核验的时间或时间范围、地点、真实参与者、可证实的同场关系、制度阶段和已知公开结果；玩家、Character 与 AI 均不得改变。 |
| 可模拟空白 | 明确标记的原创角色、私人对话和不影响已知历史的局部经历；可以产生关系、选择、私有记忆和原创角色后果。 |
| 待核验 | 来源不足、存在实质争议或只有 AI 概括的内容；不得作为剧情因果、角色定论或发布正史。 |

史料没有记载不等于自动获得虚构许可。原创设定发布前必须检查其是否会暗中改变真实人物行踪、事件因果、时代知识、制度阶段或后来已知结果。当前历史故事不提供架空历史分支。

### 原创与架空故事

原创或架空 StoryWorld 不受真实历史时间线约束，但仍受自身已发布正史、角色动机、世界规则、当前事件和允许结局约束。运行时 AI 和玩家声明都不能覆盖这些边界。

## 产品表面

前端只围绕公开角色发现、登录门禁、角色入场、故事互动和回访恢复展开：

- 首页直接展示安妮、高力士和太平公主的真实角色数据，不使用虚构占位角色。
- 角色卡同时给出所属 StoryWorld 和一句当前处境，但不要求玩家先浏览世界目录或故事大厅。
- 前端公开角色详情统一使用 `/characters/:characterSlug`，故事互动统一使用 `/characters/:characterSlug/story`；短路由由前端注册表映射到既有 StoryWorld 与 Character 身份，不把 `characterSlug` 写入领域 Schema，也不建立 `/story-worlds/...` 前端目录或深链。
- 未登录玩家可以浏览首页和角色公开信息；点击进入故事时跳转登录，登录成功后安全返回原入口。
- 公开角色详情负责展示 Character 在各已发布 ReviewedStory 中的当前处境；只有一个可进入故事时直接使用，有多个时由玩家明确选择。它同时为新轮次选择系统预设 PlayerRole，并以 `/characters/:characterSlug/story?storyId=...&playerRoleId=...` 进入互动。
- 故事互动页是纯聊天 / 交互表面：按 `storyId` 先恢复现有轮次，无现有轮次且身份有效时只自动发起一次新轮次，随后直接展示 Character 对话、审核选择和输入区。它不重复角色介绍、故事摘要、世界说明或身份教学；加载、登录与失败恢复留在同一聊天界面内，背景与史料仅按需展开。
- 当前 Character 只能看到审核可见性允许的消息。访问另一 Character 必须由玩家显式触发并继续使用对应 Character 短路由，不能自动跳转。
- 安妮是首条落地的完整纵向链路：从首页经 `/characters/annie` 进入公开详情，再经 `/characters/annie/story` 完成自由回应、审核选择、结局、刷新恢复和重新开始；其余角色按各自内容完成后接入同一短路由结构。
- 移动端是主要游玩表面；桌面端可以提高密度，不能增加必经步骤。
- 加载、空、失败和回访状态必须真实，不得用示例内容或伪造指标掩盖。
- 产品页面不使用大段说明文案解释控件、系统边界或兜底策略；历史来源和内容分类只在玩家主动打开的参考表面呈现。

## 删除后的能力边界

以下能力不属于当前角色故事平台，也不保留新旧双轨：

- `Space` / `SpaceCharacter` / `VisitorState` 领域合同和 `/spaces` 路由。
- 真实坐标强制字段、地图、LBS、附近发现、路线规划和传统 POI 能力。
- 用户创建、店主 / owner 管理、UGC 发布、内容市场和故事密码。
- SillyTavern 角色卡导入、导出和兼容目标。
- owner 或故事世界级私有 LLM 配置、API Key 管理和店主 Token 统计。
- Home、公开关系、访客好友、私信、动态墙、陌生人匹配和全局在线状态。
- 战斗、等级、装备、竞技排行榜、下注和匹配竞技。

旧 Space 类型、服务、路由、前端客户端、ORM、迁移入口和配置兼容层已经删除，不保留兼容适配器。已有部署数据库在显式执行 008 前仍可能保留旧物理表；实际数据清退必须有明确目标、完整逻辑备份和可追踪的人工迁移，不能在应用启动时静默删除。

## 安全与隐私

- PlayerStoryState、对话、关系、选择和记忆按玩家与 StoryWorld 隔离，不进入公开发现响应；其中故事进度还必须按 `story_id` 隔离。
- 私有故事请求的登录账号由服务端可信会话边界解析，客户端不能注入任意 player ID；无有效会话时返回 `401` 且不得创建或修改玩家状态。
- 登录回跳只接受本站允许的相对路径；不得接受外部 URL、协议相对 URL 或其他可形成开放重定向的输入。
- 系统 LLM 模型、服务地址、API Key 和生成参数由部署环境统一管理；密钥不得进入前端、日志或公开响应。
- AI 输出必须经过剧情动作和持久化边界校验，不能直接修改系统内容、分故事进度、长期关系或永久结果。
- 历史儿童角色必须明确为原创，不影射或收集真实未成年人信息；禁止恋爱、暧昧、成人、性化、诱导依附、强迫和血腥猎奇内容。

## 验收标准

新增能力只有同时满足以下条件，才符合当前平台主线：

- 强化“角色发现 -> ReviewedStory / PlayerRole -> 对话 / 选择 -> 分故事进度与长期关系写回 -> 回访”闭环。
- 使用 StoryWorld、ReviewedStory、Character、PlayerRole、PlayerStoryState、StoryRun 和 CharacterRelationship 统一合同，不恢复旧 Space 双轨。
- 只让人工审核的剧情动作和确定性 CharacterDecision 改变关键状态，并让 AI 保持在已发布正史内。
- 保持玩家私有数据按玩家与 StoryWorld 隔离、故事进度按 `story_id` 隔离、长期 CharacterRelationship 在同一世界内跨故事延续。
- Character 详情负责故事选择，互动页保持纯聊天；不建立前端 `/story-worlds/...` 深链或自动跨 Character 跳转。
- 历史故事不改变经核验的时间线、地点、真实人物关系、制度阶段和公开结果；原创故事不突破自身已发布正史。
- 不违反 [WHAT_NOT_TO_BUILD.md](WHAT_NOT_TO_BUILD.md)。
- 有明确的结构化状态、权限边界和与风险相匹配的真实验证。
