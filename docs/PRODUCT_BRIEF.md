# FableSpace 产品简报

## 一句话定位

**FableSpace 是一个角色故事平台：玩家因想见一个角色而进入其所属的完整故事世界，通过对话和选择建立关系、经历事件，并在回访中延续彼此的故事。**

## 为什么做

单一 AI 聊天容易失去稳定世界、事件后果和长期关系；传统互动故事又难以让角色根据玩家的自由表达持续回应。FableSpace 将经过策划和审核的故事骨架、鲜明角色与 AI 演绎结合，让玩家不是打开一个聊天工具，而是去见一个具体的人，并让这段关系在选择之后继续存在。

## 当前主体验

```text
首页直接发现角色
  -> 选择想见的角色
  -> 查看角色当前处境；有多个已发布故事时选择一个
  -> 为新一轮确认该世界允许的预设身份
  -> 登录或确认已有登录会话
  -> 直接进入角色对话
  -> 自由对话 / 关键选择
  -> 写回该故事的进度与私有记忆，以及跨故事延续的角色关系
  -> 回访时从已有结果继续
```

角色是唯一公开入口。每个角色都属于一个拥有稳定正史、规则和后果边界的完整故事世界，并可参与该世界内一个或多个经过人工审核、可独立发布且随世界内容版本追踪的 `ReviewedStory`；平台不要求玩家先浏览世界目录或故事大厅。角色详情只呈现角色当下处境、可进入的已发布故事和必要身份选择，故事互动页直接进入聊天，不用剧情简介或解释性文案挡在角色回应之前。

玩家身份由 StoryWorld 预设：单一身份自动生效；存在多个审核身份时，玩家在开始新 StoryRun 前选择一个并由该轮次锁定。平台不设置全局身份或通用性别选择步骤。每个故事的章节、关键选择、标记和结局独立推进；同一玩家在同一 StoryWorld 中与同一 Character 的长期关系跨故事、跨轮次延续，并保留可追踪的来源。

### P0 系统故事

当前公开内容基线是两个经过策划、审核和版本化的 StoryWorld、三个 Character；按目标合同，两个世界现有内容各映射为一个已发布 ReviewedStory：

| 故事世界 | 目标稳定 `story_id` | 类型 / 参与角色 | 系统预设玩家身份 | 中央事件 |
|---|---|---|---|---|
| 1854 年宽街 | `broad_street_water_1854` | `growth` / 安妮（焦点角色） | 汤姆·里德 / 莉齐·贝尔（二选一） | 安妮抱着陶罐向玩家讨水，随后通过水源、证词和选择进入宽街霍乱事件 |
| 先天二年·虔化门 | `palace_snow_edict` | `ensemble` / 高力士、太平公主 | 内侍小使 / 宫人（二选一） | 713 年七月三日玄宗一方先制入宫；玩家核对行动、消息来源与史书定性，不改变政变结果 |

安妮验证历史题材如何通过原创见证者在固定史实边界内提供局部选择；先天二年·虔化门验证真实成年人物可以在不伪造原话、私人心理或秘密会面的前提下成为 Character。玩家只能改变记录方式和原创普通宫人的局部处境，不能改变太平公主失败、死亡与玄宗掌权等公开结果。青槐驿与临川大学是待重新设计玩家身份、角色反应和连续性的候选内容，不进入 P0 公开列表。

上述 `story_id` 是后续原子迁移必须写入托管内容和玩家状态的目标稳定标识，不由标题、数组顺序、Character 或 `content_version` 临时推导。当前代码与数据库仍是“一世界一套章节 / 结局”的旧物理结构，尚未实现多故事合同；在内容 JSON、StoryRun、分故事进度和长期关系完成同一批准版本的迁移前，不得宣称该能力已经上线。

### 角色发现

首页始终是可持续扩展的角色发现页，不是世界目录、单事件落地页或身份选择器。安妮、高力士和太平公主使用同一种普通角色卡；未来增加角色时只追加真实数据，不改变首页结构，也不使用占位角色补满版面。

安妮是**真实历史背景中的原创角色**：约十岁的伦敦穷人家女孩，不是真实历史人物，也不影射任何真实未成年人。玩家进门时，她不会先讲历史知识，而是抱着陶罐向玩家讨水；玩家要先决定是否给水、追问水源、找别处的水或求助成年人。John Snow、病例记录、宽街水泵与泵柄决策随后通过行动、证词和选择逐步出现。

### 历史内容边界

历史故事必须运行在经过人工核验的真实时间线上。事件的时间或时间范围、地点、真实参与者、制度形成阶段和已知公开结果属于不可变正史；玩家可以改变原创角色的信任、选择、去留、是否得到帮助，以及史料未覆盖且不与已知事实冲突的局部后果，不能移动历史节点、制造跨时代会面或改写真实结果。

史料不足时保持 `待核验`，不让 AI 用合理想象补成事实；当前历史故事不提供架空历史分支。历史地点作为故事事实与来源表达，不形成通用坐标字段、地图入口或 LBS 产品能力。

### 体验表达

主要游玩人群以移动端为主。手机首页先展示角色和可点击动作，进入后直接看到故事处境、固定身份、角色首句与输入区；桌面端可以扩展列表密度和辅助内容，但不能改变或拖长这条核心链路。

产品页面不得用说明性文字解释页面用途、导航方式、内容来源、系统边界或兜底策略。故事背景和玩法通过角色名、故事世界、短标签、角色对白、选择与结果自然表达；界面只保留名称、状态、短标签、动作和必要错误提示。历史来源与“史实 / 剧情设定 / 待核验”只在玩家主动打开的历史参考表面呈现。

## 核心角色

| 角色 | 目标 | 关键动作 |
|------|------|----------|
| 玩家 | 找到想见、愿意回访的角色 | 选择角色、以故事固定身份进入、对话、选择、承担后果、回访 |
| 角色 | 以鲜明立场推动所属世界的当前事件 | 提问、交易、拒绝、隐瞒、揭示线索、改变关系、承担后果 |
| 系统内容管理员 | 维护平台自有的完整故事世界 | 编辑世界设置、背景设定、ReviewedStory 与 Character，并保存经过审核的当前内容 |

当前只做系统故事，不开放用户创建、编辑或发布，不保留店主 / 创作者、角色卡导入导出或内容市场作为兼容产品面。部署环境只配置一个固定管理员账号。目标内容合同允许一个已发布 StoryWorld 同时包含已发布与草稿 ReviewedStory，但公开发现和运行时只能读取已发布故事；现有后台还没有完整的故事级审核工作流，多故事管理表面须在后续代码任务中与数据迁移一起实现，不能靠通用 JSON 编辑器绕过审核。

首页、角色卡和公开故事处境允许未登录浏览；开始、恢复或推进故事必须先登录。所有私有进度直接归属登录账号，不创建匿名玩家标识，不提供匿名进度绑定、迁移或合并。故事身份只属于当前 StoryWorld，不是账号权限、现实身份或公开社交资料。

## 核心原则

- **角色属于完整世界**：角色不能脱离 StoryWorld 成为聊天壳；主题、正史、当前事件、规则和后果必须一致。
- **故事各自推进**：StoryWorld 承载共享正史、规则、Character 和 PlayerRole；ReviewedStory 承载参与角色、开场处境、章节、关键选择、确定性角色决策和结局。不同故事的进度、标记和结局不能串写。
- **身份属于世界、锁定于轮次**：每个 StoryWorld 提供一个或多个审核 PlayerRole，包含称谓、性别、背景和入场理由；每个 StoryRun 锁定一个，平台不提供全局身份选择。
- **人工骨架约束 AI**：章节、关键选择、状态变化、确定性 CharacterDecision 和结局由系统审核；AI 在边界内演绎角色和理解自由输入，不能自行改写正史或永久状态。
- **历史时间线不可改写**：历史故事以经核验的真实时间、地点、人物关系、制度阶段与公开结果为固定边界；玩法只进入不与史料冲突的原创人物和局部空白。
- **角色必须有差异**：同一玩家面对两个角色时，应看到不同欲望、秘密、语言、开价与命运，不允许只替换姓名。
- **关系跨故事连续且有来源**：自然对话可以小幅改变好感和语气，关键选择会显著改变关系与分支；同一世界内与同一 Character 的长期关系跨故事和轮次延续，每次永久变化都记录来源轮次与事件。内部数值不直接展示，也不能靠重复闲聊刷出重大结局。
- **回访重于社交**：核心是玩家与角色的私有关系、选择和记忆，不做通用访客社交网络。
- **体验可达且包容**：移动端和窄屏必须可用，关键操作支持键盘，文本保持可读对比度；新增动效应尊重 reduced-motion，界面不得暴露玩家私有进度、对话或记忆。

## 当前优先级

优先做：

- 安妮、高力士和太平公主的角色发现入口。
- 两个 StoryWorld 的系统预设 PlayerRole，以及各 ReviewedStory 的参与角色、章节、选择、确定性角色决策、结局和回访。
- 自由对话与人工剧情动作之间可追踪、可回放的状态转换。
- 自然对话小幅影响好感，关键选择显著改变关系与可进入分支。
- 同一 StoryWorld 内分故事隔离进度，并让 Character 长期关系跨故事、跨轮次延续。
- 公开角色浏览、登录后开始故事，以及账号范围内的跨设备续玩。
- 安妮从具体讨水请求带玩家进入 1854 年宽街事件，并验证“先行动、后解锁知识”的吸引力。

当前不做：

- 地图、坐标发现、路线规划和传统 POI 搜索。
- 用户创建、店主管理、UGC 供给和内容市场。
- SillyTavern 角色卡导入、导出和兼容合同。
- 无边界访客社交、私信、动态墙、陌生人匹配。
- 战斗、等级装备、竞技排行榜等传统游戏化系统。
- 运行时 AI 自行创建正史、永久结局或不可回放状态。

## 典型场景

**玩家进入安妮故事**：在首页选择安妮，角色详情呈现她此刻抱着缺口陶罐寻找水的处境，并让玩家从原创角色“汤姆·里德”与“莉齐·贝尔”中选择本轮身份；进入后直接看到安妮的回应与输入区。安妮分别称玩家为哥哥或姐姐；称呼来自 StoryRun 锁定身份，不是身份卡名称。玩家可以给水、追问水源、另找水、求助成年人或拒绝；安妮根据对话和选择改变语气与信任，历史线索在行动后逐步出现。

**玩家进入先天二年·虔化门**：选择高力士或太平公主后，从系统审核的成年“内侍小使”与“宫人”中选择本轮身份，进入同一历史事件。两个身份只能核对门次、名单、抄本与消息来源，不能调兵、传诏、替真人作出历史决定，也不能改变太平公主一方失败的固定结局。高力士与太平公主的自由回应统一显示为带“剧情转述（非史料原话）”标识的第三人称转述，不生成真人第一人称原话，不补写私人心理、密谋细节或无同场证据的会面。

**回访**：系统按 `story_id` 恢复该故事的活动轮次、关键选择、标记、结局摘要和私有记忆，同时恢复玩家在该 StoryWorld 中与当前 Character 的长期关系。故事进行中不能撤销关键选择；到达结局后可以开始新一轮，新轮次重置该故事的轮次进度，但不会抹掉已经写入长期关系且带有来源的结果。

## 一句话总结

FableSpace 要成为一组因角色而被进入、因选择而产生后果、因记忆而值得回访的故事世界。
