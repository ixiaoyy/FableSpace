2026-09-08 最新目标以 [两阶段开发目标](PHASE_PLAN.md) 为准：第一阶段完整复刻星露谷，第二阶段补充和替换原创内容。下文已实现事实继续作为历史记录，旧的十系统范围上限与提前转型条件已取消；未启动能力仍需拆分任务实施。

用户已明确要求完整迁移到 Godot + GDScript，以原生桌面版为正式产品方向、同工程 Web 为试玩入口。现有玩法、原生界面与独立存档已接入，默认本地运行/构建已切换；真人完整验收和公开部署仍未完成。下文 Phaser/Vue/Tauri 描述仅是旧实现来源，不再约束新引擎。名称、真实城市生成及新玩法未在本轮改变，实施与限制见 [Godot 工程说明](../apps/mirror-island/godot/README.md)。

## 一句话定位

一款分两阶段开发的像素生活游戏：第一阶段完整复刻《星露谷物语》的内容与体验，第二阶段补充、替换镜像岛自己的内容。

## 核心合同

- 第一张正式地图结构固定：玩家农场向右连接小镇，北侧预留山地/矿区，南侧连接河流/湖泊；不再反复调整总体布局。
- 玩家、资源、背包、制作和农田由本地 GDScript GameSession 唯一处理；Godot 场景/界面发送命令并渲染 snapshot，不经过实时后端。
- World Foundation、Farm Showcase、`life-loop-v1`、Town Gate A/B/C 与 Town Population MVP 保留历史验收；当前 Godot 已在这些底座上扩展到 12 个区域、六种普通春作、四项生活技能、仓储出货、品质肥料、围栏和湖河钓鱼。历史验收不代替后续批次的真人验收。
- 房屋、伙伴工作和基地权限保留为后续主线能力，不进入首个纵向切片。
- 当前托管 Web 入口是纯本地无账号试玩；不显示或调用注册、登录、论坛账号、账号设置或云存档入口。
- 玩家存档、背包和世界状态由本地 GameSession 处理并写入 IndexedDB；实时玩法不经过服务端。
- `One Beautiful Slice` 已在真实生产浏览器通过验收并冻结为 Farm v1；除明确碰撞缺陷外，不再重排构图或继续添加装饰。
- 客户端固定为 Godot 4.7.2 + GDScript；Windows 原生与 Web 由同工程导出，Tiled 作为当前地图来源。SaveRepository 隔离 Web IndexedDB 与桌面原子文件；Steam SDK 仍未接入。
- Ninja Adventure 只保留室内技术占位；VectoRaith Farming Sim Gate C 已冻结并正式成为 Farm v1 美术底座，Town Gate A 也已按同一完整图集正式化。生产直接加载 6 张官方 Original/16×16 图集。

## 长期玩法方向

长期核心循环是：家园种田、采集、钓鱼与采石 → 将不同产出投入跨日目标 → 看见小镇设施与居民生活永久改善 → 使用新设施提高后续生活效率 → 继续经营农场与建立关系。

- 第一阶段完整参考原作的系统、内容、流程和体验，建立逐项对照；第二阶段再补充或替换原创内容。素材来源与授权继续按媒体规则执行。
- 仓储出货、技能、矿洞、四季、自动化、鸡舍、加工、烹饪和共建继续作为先行批次；完成后仍须补齐完整原作对照中的缺口。
- 每个阶段规划前必须先核对当前代码和《星露谷物语》对应机制的可追溯资料，记录参考事实与经用户批准的偏离；数量、时长、容量、概率和层数不得由 AI 自行猜测。
- 现有三个小镇共建项目仅为先行批次的闭环验证，不代表完整原作社区内容已经对齐。
- 地表资源已提供基础镐/镰刀、石料/植物纤维、固定石块和杂草；浅层无战斗矿洞可作为先行 planning，但后续完整 120 层矿洞、生命、武器、敌人、掉落、Combat skill 与冒险家公会已明确为转型前必达项。
- 家园猫狗保持生活伙伴定位，不发展为战斗、远征、自动化或复杂养成框架。
- 东方志怪和《聊斋》属于后期独立异闻故事世界；普通探索继续使用像素世界，关键剧情未来可单独评审 CG、文字和授权语音。
- 用户已选定 A「清新田园」作为后续美术方向：明亮配色、清晰像素轮廓与轻快田园比例，先统一五件工具和小屋内外，再扩展农场与小镇。美术以质量和风格统一为准，不设成熟素材与自制素材比例，也不要求全部开源；现成素材达不到要求时可以自行制作。始终坚持“一张精美地图优先于十张粗糙地图”。示例获选不等于正式素材已替换，制作与发布标准见 [游戏美术资源规范](IMAGE_ASSETS_SPEC.md)。
- 生活世界中的探索采用看见异常 → 获得线索 → 主动尝试 → 明确反馈 → 留下变化的手工设计语言，优先复用现有地图、工具、时间与 NPC，不以战斗、物理沙盒或通用框架制造体量。详细原则见 [镜像岛探索设计原则](EXPLORATION_DESIGN_PRINCIPLES.md)；该文档只作为未来候选评审依据，不改变当前基础盘阶段顺序，也不自动授权任何探索功能实施。

## 已否决方向：镜门远征（2026-09-04）

用户明确表示不喜欢“镜门远征”提案，该方向已经淘汰，不是暂停等待重启：

- 不再把镜门、异域 run、Expedition Cargo、撤离损失、抓宠、肉鸽或塔防作为镜像岛长期核心循环。
- 不通过改名、缩小地图或包装成“微远征”继续推进同一提案。
- 既有 `09-01-mirror-gate-expedition-prototype` 等规划文件只保留历史证据，不构成产品候选或实施授权。
- 未来若用户提出新的冒险玩法，必须从新的明确需求重新规划，不能恢复旧远征 PRD 的地图、状态或框架。

开发判断固定为：当前功能是否让正在验证的核心循环更好玩；仅因“以后可能有用”或“架构更完整”而增加的框架暂缓。优先顺序为：可玩 → 好看 → 好玩 → 内容扩展 → 技术完美。

## 试玩进入体验

2026-09-06 用户明确要求正式角色支持上中下分层及性别/换装：头部、上装、下装独立组合，衣服不按性别锁定；新游戏可定制，继续已有农场后可打开外观界面修改并保存。取消九个整人预设的选择入口。角色功能在正常 `/` 运行，不依赖候选链接；切换只改变外观，不影响背包、金币、位置或世界进度。

玩家访问 `/` 后直接看到“新游戏 / 继续游戏”，客户端不发起 Keycloak/OIDC 请求。同一 origin + 浏览器 profile 只使用一个固定本地试玩槽；清除站点数据会丢失进度，且不支持跨设备同步。

旧账号派生的 IndexedDB 记录保持原样但暂时不可达，不枚举、删除、覆盖、合并或迁移。Keycloak、论坛 OIDC bridge 和数据库基础设施保留，独立注册关闭。

## 数据原则

- Keycloak 和游戏数据库分库/分凭据，游戏库不复制密码或论坛凭据。
- 旧 `localStorage` 角色名、外观和进度全部丢弃；新版只精确删除已知 `farm-game.save.v1`–`v4` 键。
- IndexedDB 保存本地 GameSession；Keycloak、Prisma/PostgreSQL 作为未启用的身份及未来云存档、成就和排行榜基础设施保留，不进入客户端启动或实时循环。
- 开发阶段的本地玩法存档只保证 current schema：新增状态时不迁移、回填、备份或兼容此前开发版本，验收从清理站点数据后的新游戏开始；current 版本内的严格解码、原子保存、刷新恢复仍必须正确。该政策不适用于论坛、身份、数据库、媒体或部署数据。

## 成功标准

- `/` 只显示镜像岛，`/mirror-island/` 跳转到 `/`，无旧界面或备用路由。
- 无 Keycloak session 且身份服务不可达时，`/` 仍直接显示新游戏/继续游戏，全程无 Keycloak/OIDC 请求。
- 不启动游戏后端时，玩家仍能完成采集、背包、制作、锄地、播种、浇水、生长和收获。
- “新游戏”创建本地世界；“继续游戏”从 IndexedDB 恢复玩家、背包、资源和农田。
- World Foundation 只有在真人从农场向右进入小镇、进出种子店、返回农场并刷新恢复后才算完成；默认主视图是 16px Tiled 游戏世界，正式 TMJ 由 Tiled 手工维护。
- Farm Showcase 的整图、2× 出生镜头和真实生产浏览器路线已通过；视觉方向不再阻塞 Life Loop。
- 当前 Godot 使用封套 13 / 状态 25：保留春季玩法和地表工具，并接入背包、制作、仓储出货、四项生活技能、品质肥料、围栏和湖河钓鱼；完整路线须经真人验收。Day 28 正常进入 Day 29，继续 spring-content，不提前进入空内容夏季。
