## Purpose

本文件登记 Town/Stardew 主线中已经明确需要、但尚未实现或尚未批准进入开发的能力。它不是“已完成”清单，也不自动授权实施；每一阶段进入代码前先确认独立范围，并更新权威产品合同与验收标准。

任何 Town 任务在收尾时若主动推迟了玩家可感知能力，必须在归档前把该能力、依赖和触发条件补到这里，避免只留在聊天记录中。

## Current baseline

当前运行时为 Godot 4.7.2 + GDScript，本地及远端 `main` 代码基线为 `0996ea37`。存档封套 13 / 状态 25 已包含 12 个区域、六种普通春作、春季野种、四项生活技能、首批职业与配方、品质肥料、仓储出货、围栏和湖河钓鱼；公开试玩仍无账号、无实时后端。

小屋、物品图标、种田动作、种子店和铁匠铺精修均已进入 main。当前角色使用已登记的分层 Godot 素材与组合外观，不再使用旧九预设选择入口。真人美术、触摸手感、200% zoom、真实存档介质和当前部署仍按批次保留未验收项。

历史 v9 / v10 / v12 / v13 只解释旧 Phaser 阶段和迁移来源，不能覆盖当前 Godot 版本或替代后续验收。开发存档只支持 current schema，不迁移、覆盖或删除旧版本记录。

## Final integration planning — 小镇共建簿 v1

用户于 2026-09-04 确认参考《星露谷物语》的长期社区进度结构，但不复制其具体内容。小镇共建簿当前只获准规划，尚未批准实施：

- Day 8 同时开放春耕、山路与湖岸三个项目，逐项投入且不可取回；作物/鱼采用候选槽位，修缮材料采用固定需求。
- 春耕建成公共苗圃，每周选择一种现有种子领取 3 粒；山路恢复山泉，可补水且每日首次恢复 15 体力；湖岸修好旧码头并开放偏向暮鲈/青鳞鱼的深水钓位。
- 三项完成后的下一晴天首次进入 Town，八名现有居民提供一次 30～45 秒完成仪式；不建设通用过场或节日系统。
- 地表采矿与镰刀已获单独实施批准并完成：开局基础镐/镰刀、石料/植物纤维、现有七个室外石块和三图固定杂草；Foothills 是石块唯一可持续刷新点，杂草按三区 1/2/1 有限恢复，不开放矿洞或干草系统。自动检查与 Farm 隔离浏览器触控路线通过，完整真人手感待反馈。
- 开发期本地 gameplay save 只保证 current schema，不维护此前开发版本迁移；外部服务与数据库保护规则不变。

## T6 — 玩家外观扩展

优先级：取得同风格专用素材后。

- [x] 新游戏先选择真实生效的角色预设，并随 IndexedDB 存档恢复。
- [x] current save 保存所选外观；不恢复旧 Ninja/Samurai 或 localStorage 字段，不迁移旧开发存档。
- [ ] 引入与 VectoRaith 16×32 比例协调的专用分层玩家素材，至少覆盖发型、上衣、下装和鞋子。
- [ ] 分层素材必须为四方向完整动画，统一锚点、遮挡顺序和工具动作；不得只做创建页静态头像。
- [ ] 增加发色、衣色等有限调色时，颜色语义由 appearance contract 保存，贴图 URL/frame 仍只属于 client。
- [ ] 是否允许游戏内通过衣柜重新编辑外观，需在角色创建稳定后单独确认，不与首版自动捆绑。

依赖：明确许可且允许 Web/CDN 分发的同风格素材；CC-BY-SA/GPL 等强 copyleft 项必须另行评审，不能为增加选项混入比例或画风不一致的包。

## Promotion rule

路线图条目进入实施前必须：

1. 明确玩家价值与最小可玩闭环。
2. 核对前置能力是否完成并经过真人反馈。
3. 在权威文档中记录独立目标、技术设计、实施顺序和验收标准。
4. 更新 `PRODUCT_BRIEF.md` 与 `WHAT_NOT_TO_BUILD.md` 的当前边界。
5. 只运行与该批直接相关的最小检查，不用路线图作为扩建测试矩阵的理由。
