# 增加角色创建与继续游戏入口

## Goal

让陌生玩家第一次打开游戏时先建立一个最小但真实的“这是我的角色”身份，再进入农场；回访玩家先看到自己的名字、外观与当前天数，然后明确选择继续。体验节奏参考《星露谷物语》的“标题菜单 → 创建角色 → 进入世界”，不复制其视觉、文案、角色、UI 或其他受保护表达。

## Background

- 当前 `/` 无条件挂载 Phaser，首次访问直接出生在农场，没有角色选择、命名或继续入口。
- 当前存档 `farm-game.save.v1` 只保存 `day`、`scene`、`spawn_id`；已上线玩家可能已经有合法 v1 进度。
- 当前正式采用的男性角色资源是 Ninja Adventure 的 `ninja_blue/sprite.png`。同一官方 CC0 固定提交中的 `samurai_green/samurai_green.png` 已核对为 64×112，并与现有角色共享 16×16、四方向帧合同；本轮把它作为女角色正式采用、上传和登记。
- 游戏仍然不登录、不连接 API 或数据库；角色信息只保存在当前浏览器。

## Requirements

### R1 — 首次进入与角色创建

- 首次访问直接显示带原创标题的单页入住卡，不先增加一层“开始”按钮，也不挂载 Phaser。
- 玩家在入住卡里从“男角色 / 女角色”两种外观中选择一种并填写名字。
- 两种选择只决定角色外观，不带职业、属性或玩法差异。
- 名字按 NFC 规范化并去除首尾空白，允许 1–12 个 Unicode 字符，拒绝控制字符；提交与存档解码使用同一规则。
- 表单通过后点击“搬进苔野”，才创建第 1 天农场存档并挂载游戏。

### R2 — 回访与重新开始

- 合法新存档显示角色预览、名字、当前天数和“继续生活”。玩家明确点击后才挂载 Phaser。
- “重新开始”使用模态确认；确认只进入新的建角草稿，不立即删除或覆盖旧存档。
- 只有新的名字与外观最终提交成功时才覆盖旧存档；取消或返回继续保留旧进度。
- 本轮只有一个本地存档，不增加存档槽、存档列表、云同步或回滚。

### R3 — v1 进度兼容与损坏状态

- 仅迁移当前农场游戏键 `farm-game.save.v1`，绝不读取旧 FableSpace 存档或业务数据。
- 当 `farm-game.save.v2` 不存在且 v1 合法时，显示“补一张入住卡并继续”；建角提交后保留原 `day`、`scene`、`spawn_id`。
- v2 存在但损坏时不回退并复活 v1；显示可理解提示并允许创建新生活。
- v2 写入成功后才删除 v1。写入失败时不删除旧档，并提示本次进度可能无法保留，但仍可在当前内存会话游玩。
- localStorage 不可访问时允许创建内存会话，并明确存档不可持久化。

### R4 — 运行时身份一致性

- v2 存档增加稳定 `player_name` 与 `avatar_id`，场景切换和睡眠必须无损保留。
- React 将一次性、已校验的初始存档传给 Phaser；BootScene 不在资源完成后重新读取 localStorage。
- 游戏角色必须使用所选男/女外观，HUD 显示玩家名字与第 N 天。
- 输入表单时 Phaser 尚未挂载，键盘输入不会被游戏按键监听抢占。
- React 只持有入口状态与表单草稿，不镜像逐帧位置、碰撞、场景或睡眠状态。

### R5 — 视觉与可访问性

- 保留“苔野小屋”的深林、胡桃木、旧纸和像素机柜方向；入住流程占据当前 3:2 游戏区域，避免布局跳动。
- 两个外观预览与实际游戏分别使用已登记的男/女角色图集，不用 DOM 假预览或运行时占位绘制。
- 外观选择使用原生 radio group；名字有真实 label、错误关联和焦点回归。
- 名字输入可按 Enter 提交；建角页可返回标题。重开模态默认聚焦安全取消操作，并可用 Escape 关闭。
- 选择态不能只靠颜色；所有按钮、输入和选项提供可见 `focus-visible`。
- reduced-motion 下不依赖动画完成流程。

## Acceptance Criteria

- [ ] 清空两个游戏存档键后访问 `/`，先看到标题入口而不是农场；完成外观和名字后进入第 1 天农场。
- [ ] 男、女两个外观在建角预览与 Phaser 角色中一致可辨；实际移动、动画、碰撞和遮挡不回退。
- [ ] 空名、纯空白、超过 12 个 Unicode 字符或包含控制字符时不能提交，并把错误关联到名字输入。
- [ ] 刷新后看到自己的名字、外观与当前天数；点击“继续生活”恢复原 `scene` 与 `spawn_id`。
- [ ] 场景切换和睡眠后 `player_name`、`avatar_id` 不丢失，一次睡眠仍只增加一天。
- [ ] 合法 v1 存档进入补资料流程；提交后生成 v2 并保留原日期、场景和出生点。
- [ ] 损坏 v2 不回退到 v1；重新开始在最终提交新角色前不覆盖旧 v2。
- [ ] StrictMode、重试和入口状态切换不会产生多个 Phaser canvas 或重复键盘监听。
- [ ] 论坛仍是普通 HTTPS 新标签页外链，网络请求不包含旧 API、认证、LLM 或数据库。
- [ ] Typecheck、production build、changed-scope React Doctor 和桌面浏览器完整入口/继续/迁移/重开验收通过。

## Out of Scope

- 复杂捏脸、发型/服装部件组合、性别、生日、喜好、农场类型和属性差异。
- 多存档槽、账号、论坛身份、API、数据库、云存档、多标签页同步和跨设备同步。
- 第三个角色、四配色或复杂外观系统、完整素材包、NPC、工具、种地、经济或其他玩法扩展。
