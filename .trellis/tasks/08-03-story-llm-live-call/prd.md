# 修复生产 StoryWorld 真实 LLM 调用

## Goal

恢复生产环境 Character 故事对话的真实模型回复，并让发布流程在替换后端前验证现有公共福利模型路由确实可调用，而不再只验证配置对象能够构造。

## Background

- 生产 UI 已从“故事对话配置暂不可用”变为“安妮暂时没有回应”，证明 `LLMConfig` 已构造成功，失败发生在 provider 请求或空回复阶段。
- 当前 `custom` provider 会吞掉每个候选端点的具体异常，部署预检也不发送真实请求，因此健康检查和配置预检均可能通过而故事对话仍不可用。
- 生产安全探针已确认正确端点返回 HTTP 500、备用路径返回 404；这证明生产 DNS/TCP/TLS/HTTP 出口可用，不需要代理。相同代码使用本地当前 Key 返回非空结果，差异集中在生产从旧备份恢复的 Key。
- 用户授权通过生产服务器调试，并要求最终修复提交、推送到 `main`。用户愿意在证据确认服务器出口需要代理时提供订阅 URL。

## Requirements

- 继续复用生产已有 `FABLEMAP_DEFAULT_FREE_LLM_*` 与其 Key 指针，不引入第二套模型配置或复制 Key。
- 生产诊断不得连接数据库，不得记录 Key、认证头、用户消息、完整 prompt 或 provider 响应正文。
- `custom` provider 失败必须保留足以区分 HTTP 状态、DNS、TLS、超时和响应格式错误的安全诊断，同时维持客户端统一 `503 dialogue_unavailable`。
- 发布流程必须在替换运行中后端前，使用新镜像与真实 Compose 环境执行固定、非用户文本的最小 provider 调用；失败时保留当前后端并明确失败类型。
- 仅当生产探针证明为网络出口问题时才配置代理；代理如需安装，应限制在 FableSpace 后端的 provider 出口范围，不改变数据库或全机无关服务。
- 通过受保护部署 Secret 把本地已有同名 `OPENCODE_API_KEY` 同步到服务器原目标；不得新增第二套运行时变量或在命令参数、仓库、日志中暴露值。

## Acceptance Criteria

- [ ] 生产探针使用现有公共福利路由返回非空结果，日志不包含敏感值或响应正文。
- [ ] 生产 Character 对话请求不再返回“暂时没有回应”的 `503`，能得到 Character 回复。
- [ ] 部署中的 provider 探针失败会发生在容器替换之前，现有后端不会被新镜像覆盖。
- [ ] 安全诊断可把代理类网络故障与鉴权、模型、路径或响应错误区分开。
- [ ] `py -3 -m compileall -q apps/api/src` 通过，部署脚本/工作流语法得到最小验证。
- [ ] 相关部署文档和 Trellis 规范记录“配置就绪不等于 provider 可用”的契约。
- [ ] 只提交本任务文件，不包含用户原有脏工作区改动；提交并推送 `main`。

## Out of Scope

- 数据库读取、迁移或玩家 StoryRun 数据修改。
- 修改 StoryWorld 剧情内容、角色 prompt 或前端选择呈现。
- 未经网络证据安装全机代理或更换模型供应商。
